# Practicum Future Roadmap

This folder captures long-term product, platform, and business ideas that extend beyond the open-source core backlog.

## Guiding Principle

Practicum should always maintain a high-quality open-source core product. The core should remain useful, complete, and trustworthy without requiring paid features.

Paid features should generally focus on scale, collaboration, hosted services, commercial distribution, convenience, advanced analytics, and enterprise operations rather than blocking the basic ability to create, import, validate, and run labs locally.

## Paywall Philosophy

### Keep Open Source

- Local Windows application
- Local API
- Local Docker runtime
- Basic Designer Mode
- Basic Import Mode
- Lab validation
- Manual authoring
- Lab manual flyout
- JSON spec import/export
- Ability to run instructor-provided labs locally
- Public spec format and documentation

### Reasonable Paid Features

- Hosted marketplace distribution
- Paid lab sales and revenue share
- Private marketplace listings
- Advanced visual designer tools
- Team collaboration
- Classroom roster management
- Student progress dashboards
- Assessment automation
- Cloud sync
- Institution admin controls
- SSO and identity integrations
- Premium support
- Managed hosting

## Monetization Concepts

1. **Marketplace Revenue Share**
   - Instructors, schools, and creators can publish free or paid lab specs.
   - Practicum takes a platform fee from paid sales.
   - The open-source app can still import compatible specs from anywhere.

2. **Creator Pro Tools**
   - Advanced authoring, templates, versioning, previews, publishing workflow, and sales analytics.
   - Basic authoring remains open source.

3. **Classroom / Institution Plans**
   - Hosted classroom management, student progress tracking, assignment distribution, and admin controls.
   - Local single-user learning remains open source.

4. **Enterprise Support**
   - Paid support, deployment guidance, private registries, custom integrations, and compliance features.

5. **Managed Runtime Later**
   - Optional cloud-hosted labs for users who cannot run Docker locally.
   - This should be additive, not a replacement for the local OSS runtime.
